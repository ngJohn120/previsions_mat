# Vercel-Compatible Official PDF Renderer Design

**Status:** Approved architecture; implementation not started.

## Goal

Deploy the existing paper-faithful SILOE ReportLab renderer on Vercel without changing the official A4 landscape document, while keeping PDF preview and download protected by the app's existing Supabase RLS boundary.

## Decision

Use a **private Vercel Python Function** for ReportLab rendering. The Next.js application continues to authorise the current user and load the fiche under RLS; it sends only a signed, serialised PDF payload to the renderer. The Python Function does not query Supabase and does not hold a service-role key.

The browser preview renders the returned official PDF client-side with PDF.js. The explicit download button receives the same protected PDF route. There is one renderer and one document output.

## Non-goals

- Do not recreate the document in HTML, Chrome/Puppeteer, or a second JavaScript PDF layout engine.
- Do not introduce a second hosted PDF service for this temporary trial.
- Do not create a Vercel/Supabase preview environment.
- Do not change the approved PDF geometry, font family, headings, table layout, watermark, signature placement, or French product copy.

## Current failure

`src/lib/print-pdf.ts` executes `spawn("python", ["scripts/rendu_pdf.py", ...])`. This works on the Windows development machine, but a Vercel Next.js Node Function cannot rely on that local interpreter or its installed ReportLab dependencies. The current preview also sends PNG data URLs generated by `pypdfium2`; that response format is unsuitable for Vercel's 4.5 MB Function payload limit.

## Target request flow

```text
Authenticated browser
  │
  ├─ GET /impression/{ficheId}
  │     └─ Next.js validates session and RLS access; renders the protected page shell.
  │
  ├─ Preview component fetches GET /impression/{ficheId}/pdf
  └─ Download button fetches GET /impression/{ficheId}/pdf
              │
              ▼
Protected Next.js PDF route
  1. Validates the authenticated session.
  2. Loads the fiche with getFicheForUser(ficheId) under RLS.
  3. Converts it to the PDF-only serialisable payload.
  4. Signs the exact request body with PDF_RENDERER_SECRET and a short timestamp.
  5. POSTs it to /api/render-pdf on the same Vercel origin.
              │
              ▼
Private Vercel Python Function
  1. Rejects missing, invalid, or expired signatures.
  2. Validates the payload shape and content bounds.
  3. Runs the existing ReportLab layout engine against that payload.
  4. Returns application/pdf bytes only.
```

The Python endpoint is technically reachable at a URL, but it accepts only HMAC-authenticated server-to-server requests. Browsers never receive the renderer secret and cannot use the renderer as a data-bypass endpoint.

## Security contract

### PDF data payload

The Next.js server sends only fields required to render the official form:

- fiche id and status;
- section, class, course, sub-branch, teacher, and school-year labels;
- ordered template/fiche rows;
- row type, calendar labels, and printable cell values.

It excludes sessions, role records, Supabase keys, profile contact details, audit data, and arbitrary client input.

### Renderer authentication

- Environment variable: `PDF_RENDERER_SECRET`, a new high-entropy server-only secret in Vercel Production.
- Next.js creates an HMAC-SHA-256 signature over the exact JSON request body and timestamp.
- The Python Function compares the signature in constant time and rejects timestamps more than 60 seconds old.
- The renderer returns `401` for unauthenticated internal calls and never falls back to arbitrary fiche-id lookups.

### Access guarantee

The existing public route remains the sole user-facing entry point. It calls `getSessionUser()` and `getFicheForUser()` before contacting Python. Teachers remain limited to their own fiches; section admins remain limited to their section; unauthenticated requests remain `401`.

## Rendering design

### Preserve the existing ReportLab layout

Extract the current rendering logic into a reusable Python module with a pure entry point:

```python
def render_pdf(payload: PdfPayload) -> bytes:
    """Build the approved A4-landscape official PDF from authorised data."""
```

The module keeps the current ReportLab details unchanged:

- landscape A4 dimensions and measured frame;
- Source Sans TrueType fonts and font family registration;
- measured table height with the existing safety margin;
- section-specific column widths;
- two-pass page numbers;
- official header, watermark, and signature placement;
- PNG rasterisation removed from the Vercel runtime only.

The current CLI remains for local document generation. It loads local data, maps it to the same `PdfPayload`, and calls `render_pdf`; it no longer owns a separate rendering implementation.

### Time zone

The signature date must use `Africa/Lubumbashi`, not the Vercel runtime's default UTC date. This prevents an incorrect official date around local midnight.

## Preview design

Create a client-only `PdfPreview` component:

1. Fetch the already-authorised `/impression/{ficheId}/pdf` route with the browser session.
2. Render the returned PDF using PDF.js and its worker into stacked canvases.
3. Retain the current page order, toolbar, document size, and visual layout.
4. Show a French loading state while rendering and an actionable French error state if rendering fails.

The visible pages remain a preview of the exact downloadable PDF, not a recreated visual approximation. The loading/error state needs a small approved mockup before implementation.

## Local-only test and release policy

1. All implementation occurs on `feature/vercel-reportlab-pdf` in `C:/Users/Administrator/dev-worktrees/Prevision_WebApp-vercel-pdf`.
2. `master` and Vercel's `main` remain untouched during implementation.
3. Use a separate local port from the stable app. Do not start a second Supabase stack with the same project id or ports.
4. Run the normal local app path and `vercel dev` locally. `vercel dev` is required to prove the Vercel Python Function packaging and request path.
5. No Preview Supabase or Vercel preview environment will be created.
6. After every acceptance check passes locally and the user approves the release, promote the exact reviewed feature commit to `main`; Vercel then deploys Production directly.

## Acceptance criteria

### Functional

- An authorised teacher previews and downloads their own fiche successfully.
- A section admin previews and downloads only fiches in their own section.
- An unauthenticated PDF request returns `401`.
- A direct Python renderer request without a valid fresh signature returns `401`.
- Preview and download originate from the same PDF response format.
- Local `npm run dev` remains usable for PDF development.
- Local `vercel dev` successfully executes the Python Function.

### Fidelity

- A4 landscape dimensions remain 841.89 × 595.28 points.
- Primary and secondary approved PDF samples retain their measured grid positions, Source Sans fonts, page count, watermark, title/header, and signature placement.
- A maximum-content fiche produces a PDF below 4 MB, leaving margin beneath Vercel's 4.5 MB response limit.

### Safety and operability

- `SUPABASE_SERVICE_ROLE_KEY` is not used by the Vercel Python renderer.
- `PDF_RENDERER_SECRET` is server-only and never uses a `NEXT_PUBLIC_` prefix.
- Python writes only temporary files in `/tmp` and cleans them up.
- Vercel Function errors surface as useful French route errors without leaking secrets or stack traces.
- The production deployment is not promoted until all local checks are recorded as passing.
